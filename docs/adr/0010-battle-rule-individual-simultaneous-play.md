# 対戦は個別同時プレイとし、結果は永続化しない

対戦モードのルールは**個別同時プレイ**とする。両者はマッチ成立時にサーバが確定した同一の山札を同一順序で各自のペースで打ち、リアルタイムに共有されるのは相手の取得札数のみ。札の取り合いはしない。勝敗は、ランダム＝60秒終了時にスコアが高い方（同点は引き分け）、タイムアタック＝先に自分の10枚を打ち切った方。対戦の結果は DB に保存しない（プレイ記録・ランキングの対象外）。

**理由**: 本物のかるたのような「同じ札の早取り」は、サーバでの取得裁定が毎札必要になり回線遅延がそのまま勝敗に直結する。個別同時プレイなら勝敗に効く通信は「どちらが先に終わったか」の1点だけで、そこだけサーバが行ロックで裁定すれば公平にできる。成績はクライアント申告（数値のみホワイトリスト）だが、友達同士のカジュアル対戦という前提で許容する。結果を保存しないのは今回のスコープ判断（プレイ履歴はスコープ外）で、`game_mode` enum の拡張も不要になり ADR 0005 の「プレイ記録は game_results 一本」を崩さない。

## Considered Options

- **(却下) 共有札の取り合い** — かるたらしさは最上だが、全札でサーバ裁定＋遅延補正が必要になり、実装も公平性の担保も一段重い。design.pen のモック数値はこの案も示唆していたが、仕様文（「どちらかが先に10枚取得」）と実装コストから個別同時プレイを採った。
- **(却下) 対戦タイムアタックでもスキップ可** — ソロのスキップは +10秒ペナルティだが、対戦の勝敗は実時間の先着で決まるためペナルティが勝敗に効かず、全札スキップで即「勝ち」できてしまう。スキップ自体を無くすのが最も単純で抜け道がない（詰まっても標準難易度の読み札全文が見えているので手詰まりにはならない）。
- **(却下) 対戦結果の game_results 保存** — enum 拡張とテーブル改修が必要になる割に、今回はプレイ履歴をスコープ外としたため使い道がない。導入するなら別 ADR で決め直す。

## Consequences

- **開始は ready 交換で同期する。** 両クライアントがマウント＋画像プリロード完了後に ready を送り合い、揃った時点で開始カウントダウンに入る。相手の ready が10秒届かなければ単独開始（フェイルセーフ）。
- **タイムアタックの勝者はサーバが裁定する。** 最初に 10 枚完走の finished を送った側を行ロックで一意に決め、`match_decided` を両者へ流す。敗者側は即座にセッションを終える。
- **ランダムは両者の申告スコアで決める。** 先に終わった側は「相手の結果を待っています」で待ち、20秒届かなければ不戦勝。
- **切断・リロードは即離脱＝相手の不戦勝。** 瞬断の猶予やセッション復帰は設けない（ADR 0006 と同じ割り切り）。プレイは60秒〜数分と短く、再戦（同じ合言葉での join-or-create のやり直し）が十分安い。
- **難易度は標準固定。** 同条件の勝負を保つため難易度選択は挟まない。対応するなら別途決める。
- **design.pen からの意図的乖離が2点ある。** ①対戦タイムアタック画面にスキップ表示がない（スキップ廃止のため） ②対戦ボタンは未ログインにも表示しログイン画面へ誘導する（機能の発見性のため）。デザイン側の更新は別途。
