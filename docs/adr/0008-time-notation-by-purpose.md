# タイムは用途別に表記する（精密タイム＝秒.センチ秒、進行・目標＝m:ss）

同じ「タイム」でも用途で表記を使い分け、全画面での表記統一はしない。記録として比較・確定される値（ランキング、ヘッダーのベストスコア、プレイ履歴、タイムアタックのゲーム中タイマー）は**秒.センチ秒**（例 `112.00`）、進行把握・目標提示の値（バッジの進捗・目標、残り時間カウントダウン、一時停止中の経過時間）は **m:ss** 系（例 `1:52`）で表記する。

**理由**: ランキングはセンチ秒がタイブレークで意味を持つため、記録系の精度は落とせない。一方バッジの目標は `1:30` の方が `90.00` より直感的に読め、design.pen の進捗例（`1:52 / 1:30`）とも一致する。コード上もこの使い分けは既に成立しており（精密タイム＝`app/frontend/lib/format-time.ts`、進行・目標＝`Badge.format_time` ほか）、どちらかに統一しても失うものの方が大きい。PR #34 のレビューで「表記の分裂」と指摘されたのを機に、分裂ではなく使い分けであると決めた（issue #35）。

## Considered Options

- **(却下) バッジ側を秒.センチ秒に寄せて統一** — 表記は1本になるが、目標 `90.00` は `1:30` より読みにくく、design.pen と乖離する。
- **(却下) 全画面を m:ss.cc に寄せて統一** — センチ秒の精度は保てるが、ランキング・ヘッダー・履歴・design すべての修正が必要で、得られるのが表記の一本化だけの割に高くつく。

## Consequences

- **同一の値でも場面で表記が変わることを容認する。** 例: タイムアタック中のタイマーは `112.00秒`、同じプレイの一時停止画面の経過時間は `01:52`。境界は「記録か、進行・目標か」の目的基準で引く。
- **m:ss 系のゼロ埋め（`1:52` と `01:52`）は規定しない。** 走行中のクロックは幅安定のため mm:ss、静的テキストは m:ss と、文脈で選ぶ。
- **精密タイムの実装は `app/frontend/lib/format-time.ts` の1箇所に集約する。** 新しい画面で精密タイムを出すときはこれを import する。
- **`Badge.format_time`（m:ss）は秒未満を切り上げる。** 切り捨てだと未達の記録（90,500ms）が目標ちょうど（`1:30 / 1:30`）に見える嘘の表示になる。ちょうど 90,000ms は `1:30` 表示かつ解錠済みなので矛盾しない。
